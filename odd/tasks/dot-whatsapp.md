## Specs

- **S1 (dual provider, owner 2026-10-13):** "dar al usuario la opción de Meta en su versión Oficial y la alternativa con Baileys" — one internal `ChannelTransport` (`start / onMessage / sendText / stop`), config switch `whatsapp.provider: baileys | meta-cloud`. Interface is *extracted* after Baileys works (no premature abstraction).
- **S2 (Engram, owner 2026-10-13):** "la memoria si se puede con engram al igual que la DB" — assistant memory = existing shared Engram; bridge DB = Engram observations (project `dot-whatsapp`): dedup `msg-<wa-id>` (duplicate_count), pinned allowlist override, liveness notes. Baileys crypto creds stay in 0700 files, never in Engram.
- **S3 (bridge pattern):** opt-in separate process, daemon ws + access key re-read per connect, backoff 1s→30s; reused from dot-telegram (`daemon-client.ts`, `protocol.ts`, MIT).
- **S4 (security, phase 1):** E.164 allowlist, anti-loop (own/status/broadcast ignored + logged), text-only DMs, no groups, no media.
- **S5 (delivery rules):** develop in own repo (fork-style), publish issue on Gentleman-Programming/gentle-dot for approval, PR only after `status:approved`; artifacts English.
- **S6 (admin API, fase 2, decisión 2026-10-23 "externo ahora, hijo después"):** bridge stays the external opt-in process (#65) and exposes a token-authed admin API on `127.0.0.1` so the gentle-dot Channels panel can drive it (sibling doc: gentle-dot-beta `odd/tasks/channels-ux.md`). Contract: HTTP JSON, `DOT_WHATSAPP_ADMIN_PORT` (default 4407), `Authorization: Bearer <token>` with token in `~/.dot-whatsapp/admin-token` (0600, created if absent), token re-read per request. Endpoints: `GET /status` → `{state: off|pairing|connected|error, provider, maskedNumber, lastActivityAt}`; `GET /allowlist` → masked entries; `POST /allowlist` `{action: add|remove, number: <full E.164>}` (hot apply via Engram pinned obs, full number never echoed back); `POST /pair/start`; `GET /pair/status` → `{qr|null, expiresInSec, attempts}` (poll); `POST /pair/regenerate`; `POST /pair/cancel`; `POST /verify` → sends "👋 dot-whatsapp vinculado" to the allowlist, returns masked per-number results; `POST /unpair` → Baileys logout + clear `~/.dot-whatsapp/auth` + state off. Numbers are masked server-side (last 4, §8/S7). Errors: 401/404/409/500 JSON. Additive only: the Baileys relay behavior is untouched (golden rule).
